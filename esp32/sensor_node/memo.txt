⏺ Done. Here's the deployment flow for TrueNAS SCALE:

  On your Mac — copy the project to TrueNAS:
  scp -r ~/Desktop/solar-api admin@<truenas-ip>:/mnt/tank/solar-api
  
  On TrueNAS — SSH in and run:
  ssh admin@<truenas-ip>
  cd /mnt/tank/solar-api
  
  # Set your password (or export it)
  export DB_PASSWORD=your_secure_password
  
  docker compose up -d --build
  
  Notes:
  - The first --build takes a few minutes (Maven downloads dependencies inside the container)
  - The app waits for MySQL to be healthy before starting, so no race condition on boot
  - restart: unless-stopped means both containers come back after a TrueNAS reboot 
  - The DB password is controlled via DB_PASSWORD env var — you can also put it in a .env file next to docker-compose.yml so
  you don't have to export it each time:
  DB_PASSWORD=your_secure_password

⏺ Found the issue. SensorData has @NotNull on temperature, but the sensor_node sketch only sends temperature, humidity, and
  location — no batteryVoltage or chargingCurrent. That's fine since those are nullable.

  The real problem is DHT11 timing on ESP32. There are two bugs in the sketch:

  1. No startup delay — DHT11 needs at least 1–2 seconds after dht.begin() before the first read. The sketch posts immediately
  at boot, gets NaN, and skips. After that it works on the 10-second interval — but if the serial monitor doesn't catch it
  you'd think it never posts.
  2. lastPostTime = 0 — on first loop iteration now - 0 >= 10000 is true almost immediately (within ~10ms), so the first read
  happens before DHT11 is ready.

  Fix: initialize lastPostTime so the first post is delayed, and add a retry on NaN instead of silently skipping.

⏺ Looks good. Two bugs were fixed:

  1. First read too early — lastPostTime is now initialized to millis() + 2000 so the DHT11 has 2 seconds to warm up before the
   first read attempt. With the WiFi connection also taking a few seconds in setup(), there's plenty of margin.
  2. Silent skip on NaN — now retries up to 3 times with 500ms between attempts before giving up. DHT11 occasionally glitches
  on a single read; a retry handles that without losing the whole 10-second window.

  Also worth checking: make sure DHT_PIN 4 matches your actual wiring. On ESP32 C3 Super Mini the pin numbering can differ from
   regular ESP32 — GPIO4 is the data pin in the sketch, confirm that's where you connected the DHT11 signal wire.
